# 04 — Phase 2 Development Plan

## Propósito de este documento en el laboratorio

Este documento continúa el método incremental usado durante los primeros 10 checkpoints y organiza la transición desde viabilidad técnica hacia validación de experiencia y aprendizaje.

## Phase 1 — Technical Feasibility

**STATUS: COMPLETED**

Los Checkpoints 0–10 demostraron:

- React foundation;
- application shell;
- prompt experience;
- simulated execution;
- declarative experience definition;
- experience engine;
- streaming;
- rich content inicial;
- resources;
- external experiences;
- second experience validation.

## Pre-Phase 2 — Demo 3 Showcase

Antes del Checkpoint 11:

`docs/demos/03-demo-showcase.md`

Objetivo:

- usar todas las capacidades actuales;
- mostrar potencial;
- servir como smoke test;
- detectar regresiones.

No agregar roadmap features.

## Checkpoint 11 — Technical MVP Review

Usar:

`docs/validation/01-technical-mvp-review.md`

Resultado:

```text
READY FOR LEARNING VALIDATION
```

o una lista concreta de blockers.

No hacer un refactor general.

## Checkpoint 12 — First Real Learning Experience

Construir el primer laboratorio pensado como contenido de curso.

Ejemplo:

**Create an Executive Summary with AI**

Debe usar:

- prompt realista;
- datos ficticios;
- output realista;
- assets;
- recursos descargables.

## Checkpoint 13 — Experience Fidelity Pass

Refinar:

- pacing;
- streaming speed;
- status timing;
- transitions;
- scrolling;
- hierarchy;
- artifacts;
- completion state.

No copiar rígidamente un proveedor.

## Checkpoint 14 — Learning Validation Session

Usar:

`docs/validation/02-learning-validation-plan.md`

Este checkpoint es principalmente observación y validación, no desarrollo.

## Checkpoint 15 — Product Decision

Tomar una decisión basada en evidencia.

Posibles rutas:

```text
Improve fidelity
Improve pedagogy
Add learner interaction
Add branching
Improve authoring workflow
Pause / rethink
```

No elegir automáticamente la opción más avanzada.

## Después del Checkpoint 15

Solo entonces definir Phase 3.

Posible borrador:

```text
16 Rich Event Model
17 Interaction Events
18 Branching
19 Experience Validation Schema
20 Authoring Workflow
```

Estos números son provisionales.

## Regla para Copilot

Cuando se solicite un checkpoint de Phase 2:

1. implementar únicamente ese checkpoint;
2. revisar documentación correspondiente;
3. preservar visual checkpoints;
4. detenerse antes del siguiente;
5. no asumir que Phase 3 está aprobada.
